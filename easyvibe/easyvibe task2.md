## 什么是IDE？

IDE=Integrated Development Environment

专门用来编辑、管理、运行和调试代码的程序，旨在最大化开发者的生产力，减少在不同工具间切换的时间成本

把写代码的过程想象成去餐厅吃饭：
VS Code 是餐厅大堂，装修豪华，环境舒适（代码高亮、好看的主题），但大堂本身不生产食物，你坐在这里，只是为了更舒服地点菜（写代码）。
环境 (Python/Node) 是后厨，真正做饭（运行代码）的地方。
插件是服务员，连接了大堂和后厨，他看得懂你的菜单，跑去告诉后厨“3号桌要一份运行main.py”。做好后，他把结果（热腾腾的饭菜）端回到你面前。
只装 VS Code = 只有大堂没后厨（只能看，不能吃）
只装 Python = 只有后厨没大堂
装了 VS Code + 插件 + Python = 完美的就餐体验

## AI IDE能做什么？

在AI IDE里，可以直接使用大语言模型帮助你进行编码和修改文件：
直接说“做一个登录页”，它先生成基础代码结构
把报错信息和相关代码丢给它，让它先分析原因并给出修改建议
在你确认后，让它自动新建文件、批量改代码，处理跨文件的体力活

## 怎么跟AI沟通更有效？

（1）说清需求
这个东西来干嘛
需要哪几块内容
用户的水平和限制
希望什么形式的产出

（2）先能跑起来，再变复杂
先要一个最小的例子
在这个基础上，慢慢把内容加完整
结构差不多之后，再考虑美化

## 用AI IDE打造专属游戏

工具：codebuddy

版本概览

v1：仓库初始版本，10 个情境 / 86 道决策题 / 像素风，仅鼠标操作，90% 通关，含生词本。
v2：在本地 AI IDE 中完成三轮迭代，新增主界面、任务卡、键盘操作与双难度模式，通关线降至 80%，并修复 6 道生硬题目。

主要变更

| 方面 | v1 | v2 |
| --- | --- | --- |
| 界面状态 | 直接进入关卡选择页 | 新增独立主界面：主界面 → 关卡选择 → 答题 → 结算 |
| 任务指引 | 仅有抽象目标与答题后解析 | 新增具体任务与 86 条分步指引；答题页任务卡实时打勾 |
| 操作方式 | 仅鼠标点击选项 | 鼠标 + 键盘（1–4/A–D 选项、Enter 下一题、R 重开、Esc 返回） |
| 反馈机制 | 进度条为主 | 进度条 + 得分/正确率/连对 + 答题飘字 + 通关印章 |
| 难度机制 | 单一模式，90% 通关，容错 1 题 | 练习/挑战双模式，80% 通关；练习容错 2 题、挑战容错 1 题 |
| 题库质量 | 改签/面试/会议共 6 题衔接生硬、解析错位 | 重写并从方案书重新生成；区分度验收 0 题不通过 |
| 功能精简 | 含生词本 | 移除生词本，保留结算页错题清单 |
| 关卡页标题 | 重复主菜单文案 | 改为「选择一个情境」并加入返回主界面入口 |
| 版本标识 | 无 | 页面标题与主界面显示 v2 |
