# task3：做出可交互原型

## 教程规定的作业要求

参考本节课的提示词和内容，完成一次完整闭环：

业务梳理提示词生成 → 单页原型生成 → 多页原型生成

成果分享：截图程序分享给大家看

思考题：为下一节"接入大语言模型（LLM）和文生图能力"预留空间，提前思考：你的工作台里，可以怎样嵌入"AI 写文案 / 生成配图 / 生成脚本"等能力？

## 我选的方向：知识卡片工作台

教程给的贯穿案例是电商内容工作台。我想做别的应用，先列了短视频脚本、旅行行程、招聘 JD、论文笔记等十几个方向，最后选了"知识卡片工作台"。原因是它能自然地套进教程要求的闭环：批量输入 → 生成草稿 → 筛选编辑 → 收藏模板复用。

在动手前先向自己提问，把想法收敛到第一版范围：

- 目标用户：正在学新领域的职场人，在批量整理资料时使用
- 要解决的问题：当我需要快速了解一个新领域并整理学习资料时，我想要把多个网址和文件批量转成结构化的知识卡片，以便于我筛选、编辑，并沉淀成可复用的知识资产
- 第一版只做：批量导入（网址 / TXT / Markdown / 粘贴文本）→ 模拟解析生成卡片 → 筛选编辑 → 存为卡片结构模板
- 第一版不做：真实网页抓取、PDF/Word 解析、建立关联、关系图、关联类型区分、多人协作、导出
- 示例领域：产品设计方法

"不做什么"这一条最关键。教程反复强调第一版范围要足够小，正因为 AI 让开发变快，才更要先服务一个小群体、拿去测试，再小步迭代。

## 写提示词的三个层次

教程给了三种写法，我在项目中都实践了：

（1）从口述开始（推荐新手）

> 我想做一个工具，帮正在学新领域的职场人整理资料。用户导入和知识点相关的网址、文件，经过处理，得到结构化的知识卡片。还可以建立知识卡片之间的关联。先做最简单的版本：批量导入 → 生成卡片草稿 → 用户筛选修改 → 存成模板复用。

把这段话交给对话模型，让它扩写成业务逻辑文档，再生成适合 AI IDE 的实现说明。AI 扩写时会补出我没想到的点，比如"要不要支持批量上传"，我再根据实际需要保留或删除。

（2）直接给整理好的业务文档

跳过扩写环节，把一页需求说明直接套进教程 2.1.2 的格式交给 AI IDE。适合范围已经想清楚的情况。

（3）让 AI 写"提示词的提示词"（进阶）

> 基于下面的想法，帮我写一个发给 coding Agent 的写代码用的提示词，我需要用这个提示词来生成代码。要求：1. 提示词要包含清晰的页面布局描述；2. 明确数据结构和交互逻辑；3. 指定技术栈（如 React + Tailwind）；4. 列出需要实现的核心功能点。

## 第一版：单页原型

给 AI IDE 的实现说明（核心部分）：

> 请参考下面的业务逻辑，实现一个单页面 Web 应用（第一版原型），用来验证核心流程。技术栈：React + Vite + Tailwind CSS。所有数据用本地状态和模拟数据，不调用任何真实 API。
>
> 1. 批量导入：网址（每行一个）、多个 .txt/.md 文件（FileReader 读取）、粘贴文本；
> 2. 模拟生成：点击后 500ms loading（骨架屏），按所选模板生成结构化卡片；字段：标题 / 一句话核心 / 关键要点 / 标签 / 来源 / 我的备注 / 关联卡片（占位）；
> 3. 筛选与编辑：按标签过滤，展开卡片编辑全部字段，增删要点，删除卡片；
> 4. 模板复用：内置概念卡/方法卡/案例卡，可把卡片"存为模板"下次套用；
> 5. 载入示例：一键载入 3 张产品设计方法领域的卡片。
>
> 第一版不做：真实抓取网页、PDF/Word 解析、关联交互、关系图、关联类型、多人协作、导出。

本地预览：http://localhost:5180/ （5173 被另一个项目占用，改到了 5180）

讨论过程中确认的 12 个点，几个关键决定：

- 教程闭环里的"收藏模板复用"对应"卡片结构模板"（概念卡 / 方法卡 / 案例卡），而不是主题卡片集
- 网址导入用粘贴 URL + 模拟解析，不做真实抓取
- 文件只支持 TXT / Markdown，一次可导入多个来源
- 卡片字段：标题 / 一句话核心 / 关键要点 3–5 条 / 标签 / 来源 / 我的备注 / 关联卡片
- 关联留到第二阶段，用系统推荐候选卡片 + 相关卡片列表，不区分关联类型

## 第二版：多页面与关联

核心流程跑通后，按教程第 3 节扩展成多页面应用。给 AI IDE 的扩展提示词：

> 请在现有单页应用基础上扩展为多页面应用，用顶部导航切换页面。
>
> 页面结构：1. 工作台页（保留原有功能）；2. 卡片库页；3. 关联视图页；4. 模板库页；5. 卡片详情页。
>
> 关联功能：系统根据标签重合与中文关键词相似度，为每张卡片推荐候选关联卡片（标签重合计 2 分，中文双字词组重合计 1 分，按总分排序取前 3 张）；点击"关联"建立关系（存入 relations 字段），可取消；用"相关卡片"列表呈现，不区分关联类型，不做关系图可视化；删除卡片时同步清理其他卡片对它的关联引用。
>
> 不引入路由库，用 React state 切换页面；保持第一版所有功能正常。

| 方面 | v1 | v2 |
| --- | --- | --- |
| 页面结构 | 单页面：导入 + 卡片 + 模板 | 5 个页面：工作台 / 卡片库 / 关联视图 / 模板库 / 卡片详情 |
| 卡片浏览 | 工作台内网格 | 新增卡片库页，点击进详情页 |
| 关联功能 | 字段占位，无交互 | 系统推荐候选卡片，可建立/取消关联 |
| 推荐规则 | 无 | 标签重合 2 分 + 中文关键词重合 1 分，取前 3 |
| 模板管理 | 工作台侧栏 | 独立模板库页，可套用、删除 |
| 数据联动 | 无 | 删除卡片时清理其他卡片的关联引用 |

实际走通的流程：载入示例 → 关联视图生成带相似度分数的候选 → 点击关联后计数从 0 变 1、出现取消按钮 → 卡片库计数同步 → 详情页正常显示侧栏。`npm run build` 构建通过，0 错误 0 警告。

## 思考题：怎么嵌入 AI 能力

教程下一节要接入大语言模型和文生图。我的工作台可以这样嵌入：

（1）AI 写文案 / 生成卡片：把现在的 `mockParse()` 替换成 LLM 调用。输入网址正文或文件文本，让模型直接输出符合卡片字段结构的 JSON（标题、一句话核心、3–5 条要点、标签），用 prompt 约束输出格式，省掉现在的文本切句规则。

（2）AI 生成配图：为每张卡片生成一张示意图（文生图），用在卡片列表的缩略图和详情页头部，帮助视觉记忆。

（3）AI 生成脚本 / 综述：基于一组卡片，让模型生成一篇主题综述或讲解稿，对应教程下一节提到的"对历史内容任务做自动归类和摘要，帮助规划下一个活动的选题"。

（4）AI 建立关联：用文本嵌入向量计算卡片相似度，替代现在的标签重合/关键词匹配规则，给出更准确的候选关联卡片；还可以让模型解释"为什么这两张卡片相关"。

（5）AI 自动归类：导入一批卡片后，让模型自动聚类打标签，减少手工维护标签的成本。

最值得先做的是第（1）项：它直接替换现有的模拟解析环节，改动集中、效果明显，输出结构正好就是已经设计好的卡片字段，不用改数据结构。

## 学习心得

这一章最大的收获是"先收敛范围，再动手"。教程给的电商案例功能很多，但我一开始就想做成"知识卡片 + 关联网络"的大而全工具。按教程的方法向自己提问、列"不做什么"之后，第一版缩到了一个单页面，反而很快跑通了。

写提示词时，"先口述再让 AI 扩写"比直接写完整提示词更适合我。AI 扩写时补出的"要不要支持批量上传"这类问题，帮我发现了没想清楚的地方。

第二版扩展关联功能时，我特意克制住了做关系图可视化的冲动，按之前确认的边界只做列表。教程说原型不需要一次完成所有功能，让用户尽早看见方案、实际操作、指出偏差才是目的。

调试中遇到的两个实际问题：一是 npm 缓存目录权限异常，改用独立缓存目录解决；二是 5173 端口被另一个项目占用，换到 5180。这些不影响原型本身，但提醒我本地环境也要留意。
