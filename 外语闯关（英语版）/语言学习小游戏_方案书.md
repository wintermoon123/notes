# 语言学习小游戏 · 方案书 v2（WorkBuddy 原生路径）

> 目标：做一款**全新的**语言学习小游戏（英语 / 韩语 二选一），HTML 单文件形态，**全程只用 WorkBuddy** 完成，**积分（Credits）总消耗控制在 1000 以内**。
> 参考：Easy-Vibe 第一章《AI 时代的编程初体验》——项目制学习、AI 原生小游戏、对话式 Vibe Coding。
> 本版相对 v1 的变化：**技术前提被修正**（见 §0），六个方案全部重做玩法描述，并新增积分可控性设计。

---

## 0. 关键修正：v1 的技术前提有误

上一版方案基于「用 z.ai 全栈开发 + GLM 计费」，但你的要求是**只用 WorkBuddy**。查证 WorkBuddy 官方文档后，三条前提需要改写：

| 项 | v1 假设（错） | v2 结论（已核实） | 对方案的影响 |
|---|---|---|---|
| 积分是什么 | z.ai 的 GLM token 计费 | **WorkBuddy Credits**：所有对话请求都扣积分；**云服务里的模型调用同样扣** | 1000 分要**同时**覆盖「我写代码的消耗」+「玩家玩的时候 AI 调用的消耗」，预算要重排 |
| 代码从哪来 | 复制提示词到 z.ai 生成 | **我在 WorkBuddy 里直接产出单文件 HTML**，用文件交付 + 本地预览 | 不需要你手动去 z.ai 操作；省掉一整轮复制粘贴 |
| 运行时 AI 怎么接 | 自建后端 / 自备 API Key / 第三方平台 | **WorkBuddy 云服务（cloud-service）提供免密钥 LLM**，纯 HTML 用 CDN SDK 即可调，玩家无需任何 Key | 真正做到「只用 WorkBuddy」，且运行时 AI 能力不受限 |

### v2 的积分约束模型（最重要的设计约束）

```
你的 1000 Credits 总预算
├── A. 生成期：我在 WorkBuddy 里产出 HTML 的对话消耗（输出 token 为主）
├── B. 运行期：玩家玩到 AI 增强功能时，云服务模型调用消耗的 Credits
└── C. 缓冲：预留 20%，用于验收后的定点微调
```

**结论：AI 功能不能做成"默认全开"，必须做成"按需 + 可缓存 + 有上限"。** 这是本方案所有设计的出发点。

> ⚠️ 关于「积分单价」：官方 Credits 文档只说明"消耗量随模型定价与任务复杂度变化"，未公开每千 token 的固定积分单价表。所以本方案**不编造单价**，改为控制**可精确计量的三件事**：调用次数、单次输出 token 上限、是否可缓存复用。实际扣减请在客户端「设置 → 积分」查看。

## 1. 六个方案（含玩法）

> 全部为**新玩法**，均非贪吃蛇衍生。玩法轴覆盖：接龙 / 消除 / 拼读 / 交际 / 产出 / 打字速度。

---

### 方案 1 · 词链接龙 Word Chain

**玩法**：屏幕中央显示当前词，下方 4 个候选词。玩家选出「能接上」的下一个词（英语按首字母接：`care → early`；韩语按首音节接：`커피 → 피아노`）。接对 → 链条 +1、连击加成；接错 → 链条断裂、扣 1 点生命，暴露正确答案并从断点续接。链条越长，单词长度递增、干扰项相似度递增、限时递减。

**AI 承担**（规则引擎做不了的部分）：
- 动态生成候选集，并刻意放入**"接得上但搭配不自然"的干扰项**（例如 `cure → in` 语法成立但生硬）
- 判断衔接的**自然度**并给出中文点评（"接住了，但更自然的是 toward"）

**双语适配**：英语接字母、韩语接音节——韩语是音节文字，天然契合。
**教学价值**：词汇联想 + 搭配，产出型。
**难度**：玩法中 / 实现中 / 运行成本 中。

---

### 方案 2 · 词义消消 Word Match

**玩法**：6×4 网格，左列目标语词卡、右列中文释义卡。点左卡 → 点右卡，配对成功双卡消除并计入连击倍率，失败则两卡轻微抖动回位。限时 90 秒，连击 ×3 时音效与配色升档。

**AI 承担**：只做两件规则引擎做不到的事——① 生成**易混词对**（影响 / 效应、离职 / 退休；`-에` vs `-에서`、`-로` vs `-(으)로`）；② 每局结算点评。
**教学价值**：再认（recognition），门槛最低，适合入门。
**难度**：玩法低 / 实现低 / **运行成本最低**。

---

### 方案 3 · 音节拼拼 Sound Builder

**玩法**：给中文释义 + 罗马音 + 打乱的音节块，玩家按正确顺序点拼。拼对后屋顶一盏灯亮起，全部拼完显示词与例句。
- **韩语模式（核心差异化）**：`한 / 국 / 어` 三块拼成 `한국어`，配罗马音与发音提示；进阶题考收音（받침）与紧音（ㄲ/ㄸ）。
- **英语模式（做变体而非照搬）**：英语按字母拼会撞上不规则动词，所以改为**给出动词原形、选择正确变形**（go → went / gone / goed），并保留拼写音节高亮。

**AI 承担**：生成罗马音、发音提示、**记忆技巧（mnemonic）**、相似词对比。
**教学价值**：直击韩语学习者最大痛点——**拼读规则**。
**难度**：玩法中 / 实现中偏高 / 运行成本 低。

---

### 方案 4 · 情境对话 Scene Quest

**玩法**：AI 扮演 NPC（店员 / 同事 / 面试官 / 地铁乘务员），给一句情境台词，玩家从 4 个候选中选最合适的回应，**或自己输入一句**。NPC 随即用目标语言回应，展开 8–10 轮完成一个场景（点咖啡 / 机场值机 / 自我介绍 / 看医生）。每轮结束给一句中文讲解。
- **韩语额外维度**：NPC 使用不同敬语阶称（하십시오체 / 해요체 / 해체），**选对阶称额外加分**——这是韩语独有的、难度真实存在的考点。

**AI 承担**：全程。NPC 台词生成、即时回应、讲解、阶称评判。
**教学价值**：情境交际，最接近真实使用。
**风险**：**运行成本最高**；响应延迟直接影响手感；必须处理超时与降级。
**难度**：玩法中 / 实现高 / 运行成本 **最高**。

---

### 方案 5 · 造句工坊 Sentence Lab

**玩法**：左侧是「AI 老师批改本」——给一个中文情景 + 3 个必须用到的目标词，玩家写一句话提交。AI 逐句标注错误类型（**语法 / 用词 / 语域 / 拼写**），给出地道改写版，中英/中韩对照讲解。右侧是历次批改记录，可对比自己的表达演进。

**AI 承担**：每题一次判分 + 讲解；需要稳定 JSON 输出（system prompt 锁死 schema）。
**教学价值**：产出型（production），直接对应写作与口语表达。
**难度**：玩法中高 / 实现中 / 运行成本 中偏高。

---

### 方案 6 · 打字雨 Type Rain

**玩法**：单词从屏幕顶部下落，玩家照着敲，敲对即碎裂消除、敲错漏掉扣分。实时显示 WPM（每分钟词数）与准确率；连续 10 个全对触发"词流加速"加速下落。结算给出速度曲线与最差 3 个词。

**AI 承担**：按当前水平生成词序列（保证难度贴合）；结算点评。
**教学价值**：拼写 + 反应速度，直观可量化。
**难度**：玩法低 / 实现低 / 运行成本 低中。

---

### 附加模块 · AI 生词卡 Wordsmith（可叠加到任意方案）

输入一个词或主题，AI 一次返回：例句 3 句 + 常见搭配 + 易混词 + 记忆技巧，生成一张可收藏的「生词卡」。适合放在结算页或做成独立小页面，**单次调用、成本可控**。

## 3. 推荐方案：词旅 LexiQuest（三段式关卡 + AI 增强层）

不押注单一玩法，而是 **「零积分核心循环 + 可选 AI 增强层」**：核心关卡 100% 本地规则驱动（运行时 0 积分），AI 只在玩家主动开启或触发时介入。

### 3.1 主流程

```
选语言（English / 한국어） → 选主题（4 个） → 关卡（三段式） → 结算 → 生词本
```

### 3.2 关卡内三段循环（约 3–5 分钟/关）

| 段 | 名称 | 来源方案 | 认知层级 | AI 调用 |
|---|---|---|---|---|
| ① | **消消·认读** | 方案 2 | 再认 | 无（易混词对预先缓存） |
| ② | **音节·拼读** | 方案 3 | 产出 | 无（罗马音预置） |
| ③ | **情境·运用** | 方案 4 | 交际 | **有，但可关**（默认开启结算点评，实时对话可选） |

错词自动进入 **生词本**，可「再练一轮」。

### 3.3 AI 增强层（全部可选 + 全部有降级）

| 编号 | 时机 | 内容 | 默认 | 缓存策略 |
|---|---|---|---|---|
| A0 | 生成期 | 预置 4 主题 × 24 词 × 2 语言（含中文、例句、音标/罗马音、音节、等级、易混词）**直接内联进 HTML** | 必做 | 内联，运行时 0 调用 |
| A1 | 开局 | 玩家自选主题 → 现场生成 12 词包 | **关** | 同主题结果存 localStorage，**同主题只调一次** |
| A2 | 结算 | AI 教练用目标语言写 3–5 句复盘 + 3 个下周重点词 | 开 | 每局 1 次 |
| A3 | 写作 | 玩家写一句 → 纠错 + 地道改写 | 关 | 用户手动触发 |
| A4 | 词卡 | 生词卡（例句/搭配/易混词/mnemonic） | 关 | 单次 |

**降级机制**：云服务调用超时 8s / 不可用 → 自动切本地模板文案，游戏不中断，角落显示「离线模式」。

## 4. 积分预算（1000 分怎么花）

### 4.1 控制手段（可精确执行的三件事）

| 手段 | 具体做法 | 效果 |
|---|---|---|
| **限次** | 每局 AI 调用上限 **2 次**（A1 主题包 + A2 结算点评），A3/A4 用户手动触发 | 单局运行成本封顶 |
| **限长** | 所有 AI 调用 `max_tokens` 硬上限 **600**，system prompt 固定复用以命中缓存 | 单次输出 token 可预测 |
| **缓存** | A1 按 `lang+topic` 缓存进 localStorage；A0 完全内联 | 重复游玩零调用 |

### 4.2 预算分配

| 区块 | 内容 | 预算占比 | 控制方式 |
|---|---|---|---|
| **A. 生成期** | 我产出 HTML 的对话：方案定稿 → 1 次完整文件写入 → 自检 → 定点微调 | **≈ 45%** | 总对话轮数 ≤ 12；单次文件输出 ≤ 15K token；修改用 Edit 定点改，不用整文件重写 |
| **B. 运行期** | 玩家实际游玩触发的 AI 调用（按 §4.1 限次限长） | **≈ 35%** | A0 内联 + 缓存复用后，**冷启动 1 局约 2 次调用**；之后同主题复用 |
| **C. 缓冲** | 验收后的缺陷修复与视觉打磨 | **≈ 20%** | 预留 |

### 4.3 消耗量估算（用 token 而非积分，口径可靠）

| 场景 | AI 调用次数 | 单次输出上限 | 输出 token 量级 |
|---|---|---|---|
| 玩家首次进入某主题 | 1（A1，生成 12 词包） | 600 | ≈ 500 |
| 玩家完成一局（结算点评） | 1（A2，复盘 3–5 句） | 600 | ≈ 350 |
| 玩家再玩同主题 | **0**（缓存命中） | — | 0 |
| 玩家手动触发生词卡 | 1（A4） | 600 | ≈ 400 |

> 结论：**1000 分在「A + B」双占用下依然可行**，前提是 A0 内联 + A1 缓存 + 每局限次。这三个开关是硬性的，不可省。

## 5. 双语内容设计

### 5.1 统一词条 schema

```json
{
  "id": "en_014",
  "lang": "en",
  "topic": "cafe",
  "word": "receipt",
  "pos": "n.",
  "zh": "收据",
  "example": "Could I have the receipt, please?",
  "phonetic": "/rɪˈsiːt/",
  "roman": "",
  "syllables": ["re", "ceipt"],
  "level": "A2",
  "confusables": ["ticket", "invoice"]
}
```

- **英语**：音标 + 词性 + 不规则动词形态提示 + 常见搭配
- **韩语**：罗马音（Revised Romanization）+ 谚文音节拆分 + TOPIK 等级 + 敬语阶称（하십시오체 / 해요체 / 해체）

### 5.2 存储格式（压缩体积，省 token 省体积）

词库内联进 HTML 时用 **紧凑 TSV**，而非格式化 JSON：

```
id|lang|topic|word|pos|zh|example|phonetic|roman|syllables|level|confusables
```

192 条词条（4 主题 × 24 词 × 2 语言）压缩后约 20KB，不撑爆单文件。

### 5.3 字体

```css
font-family: "Malgun Gothic", "Apple SD Gothic Neo", "Noto Sans KR", system-ui, sans-serif;
```
Windows 自带 맑은 고딕，韩语可正常显示；回退链保证跨平台。

## 6. 实施路线（每阶段可独立验收，积分分段释放）

| 阶段 | 内容 | 交付物 | 生成期积分 | 运行期积分 |
|---|---|---|---|---|
| **P0** | 语言选择 → 主题选择 → 消消关（本地词库，无任何 AI） | 能玩的单文件 HTML | 约 20% | **0** |
| **P1** | 音节拼拼关 + 生词本 + 英语/韩语完整词库 | 完整可玩 | 约 15% | **0** |
| **P2** | 接入 A1/A2/A3/A4 AI 增强 + 超时降级 + 积分计数器 | AI 原生版 | 约 10% | 按需 |
| **P3** | 音效、动效、移动端适配、视觉打磨 | 可发布版 | 约 5% | 0 |

**关键**：P0 + P1 完成时游戏**已经完整可玩且零运行积分**，P2 只是加挂件。这样即使预算提前见底，交付物依然成立。

## 7. 交付路径（全程在 WorkBuddy 内）

| 目标 | 方式 | 说明 |
|---|---|---|
| **本地预览**（默认） | 直接打开单文件 HTML | 双击即可；但 `file://` 下 CDN SDK 与跨域可能受限 → 故 P0/P1 不依赖任何外部请求 |
| **发布为应用** | WorkBuddy「发布为应用」→ 获得在线链接 | 静态站一键上线，适合分享给他人试玩 |
| **运行时 AI** | WorkBuddy 云服务（免密钥 LLM） | 需为该应用激活云服务环境；**Origin 白名单**可能导致本地调用被拒 → 降级通道必须先做好 |

**技术要点**：
- 免密钥 LLM 的正确接法是 CDN 引入 `@tencent-ai/workbuddy-cloud-sdk` 的 IIFE 构建，用 `createWorkBuddyCloud({ endpoint, publishableKey })` 初始化；**禁止**在前端硬编码任何 API Key，**禁止**自建 BFF 反代模型服务。
- `models.list()` 返回的模型目录可能是空数组，这是合法结果——要显式处理空态，不要写死模型 id。
- 所有调用必须 `stream: true`（非流式会被直接拒绝），且 `messages[0]` 必须是 system 消息。
